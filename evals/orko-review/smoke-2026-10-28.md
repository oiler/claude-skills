## Ambiguities and guesses

1. **An evergreen doc that doesn't govern the doc's subject.** Preflight takes evergreen docs from the doc's own repo, so the textkit CLAUDE.md became the constraint for a spec about a skill in `~/files/repo/claude-skills`. All three lenses rated the pytest test plan a blocker against it. Step 7 covers two cases: the doc is at fault (accept), or the evergreen doc may be stale (defer). A reading that the doc is at fault would have called for accept-and-rewrite. The spec's own eval plan expects the planted CLAUDE.md conflict to be accepted.
2. **A doc that records already-shipped behavior.** The doc's Status says it is synced to the v0.1.0 tag. Step 7 doesn't say how to treat a finding whose fix would make the doc describe code that doesn't exist. I adopted a rule of my own: accept when the fix documents shipped v0.1.0 behavior (verified in the tag's script), and defer when it proposes new behavior. That rule drove about 10 of the 16 defers.
3. **How deep "check the claim yourself" goes at 49 findings.** I re-verified every code-dependent claim against the tag script and the docs claims via WebFetch. I took two claims partly on the reviewer's evidence: the purged-transcript survey count, beyond confirming the oldest transcript date, and the "6 of 22" count, which my own grep put at 5. The rule that the same problem gets the same verdict doesn't cover a partial overlap. I deferred F-2, accepted F-7, and named each in the other's `--why`.

I rejected completeness/F-16 (two concurrent apply sessions on one doc) because the sequence is implausible and the impact not severe. 7. **"Five subcommands."** SKILL.md line 24 says the `allowed-tools` grant covers "the script's five subcommands". The grant is right to exclude `lint` because the orchestrator never runs it, but "the script's five subcommands" is no longer true of the script. In bypass mode this didn't matter.
