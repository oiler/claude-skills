## Defects found

1. **Final-stage parked findings lose their finding text in the report** (`scripts/orko_sdd.py`, `PARKED_RE` and `RULING_RE`).
   - Cause: `PARKED_RE` is `^Task (\d+): parked — (.+)$`, so a final-review residual has no recognized form. My `Final: parked — <finding> — Ruling: <why>` lines were picked up only by `RULING_RE`, which keeps the text after `Ruling:`.
   - Effect: the Decided table showed three rows whose Ruling column reads "real, minor, nothing builds on it…", "documented test command doesn't use -O…", and "process exits immediately…", with no finding named. These parked residuals also never reached Follow-up.
   - Scope: SKILL.md never specifies a ledger format for final-review residuals, so this is a skill/script gap, not only a script bug.
2. **The final review row always reads "dispatched"** (`render_report`: `| final review | dispatched | — | … |`). The report can't show that the final review, fix wave, and re-review finished, and there is no documented completion line for `final`. A reader of this run's report would think the final review was still pending.
3. **The Models column conflates roles.** Task 1 shows `sonnet/high, opus/low` with no indication of which is the implementer and which the reviewer. The final row lists `opus/high, opus/medium, opus/low` for three different roles. Minor.
4. **Duplicate or ragged Follow-up lines.** Skipped tasks appear both in the Done table and again in Follow-up. Ledger `Follow-up:` lines render as `- Follow-up: …` while script-generated lines render as `- Task 3 skipped: …`. Cosmetic.
5. **Branch instruction vs. native worktree tool.** See ambiguity 1. The required `feat/<plan-slug>` off `base-branch` can't be produced by `EnterWorktree(name=…)` as documented, so the skill's "consent" hand-off to `using-git-worktrees` leads into a contradiction the orchestrator has to resolve by hand.
