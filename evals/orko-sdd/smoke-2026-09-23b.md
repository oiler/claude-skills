Parked findings appear in both Decided and Follow-up. Suggested fix: say in Authority that the report emits skipped tasks automatically, so the orchestrator adds a `Follow-up:` only for the decision oiler must make. Alternatively, have the script drop parked lines from one of the two sections.
2. **The web-security trigger is underspecified (minor, docs).** "User input" doesn't say whether it covers a library function's string argument or CLI stdin/argv. The trailing "including the final reviewer…" clause reads as either conditional or unconditional. Suggested fix: state the condition once, and state separately whether the final-review roles always get the line.
3. **No rule for final-review findings declined before the fix wave (minor, docs).** SDD says the fixer gets the complete list. The skill's parked format applies only to residuals. As orchestrator, I pre-parked two Minors, which departs from SDD's text without a skill rule that authorizes it. Suggested fix: either allow a ruling to exclude findings from the fix wave, with the same parked format, or say explicitly that all findings go to the fixer.
4. **Harness friction the skill doesn't mention (observation, not a skill defect).** After `EnterWorktree(path=…)`, the harness refused any Bash call that combined `cd` or `git -C` with git work, and one call that bundled a heredoc with `git`. A project whose test or lint command runs git inside the worktree may hit the same guard.
