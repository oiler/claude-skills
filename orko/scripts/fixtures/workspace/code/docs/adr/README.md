# Architecture Decision Records

Use ADRs for consequential technical choices with meaningful alternatives or long-lived consequences. Do not use them for product scope or policy decisions.

## Naming

`ADR-NNN-short-title.md`

## Template

```markdown
---
id: ADR-NNN
title: "[Technical decision]"
status: proposed
decided_at: null
supersedes: null
superseded_by: null
---

# ADR-NNN — [Technical decision]

## Context
<!-- Technical pressure, constraints, evidence, and linked product requirements. -->

## Options considered
<!-- Benefits, costs, risks, and unknowns for each viable option. -->

## Decision
<!-- The choice and authorized decision owner. -->

## Consequences
<!-- Tradeoffs, operational effects, follow-up, and reconsideration triggers. -->
```

Accepted ADRs are superseded rather than silently rewritten.
